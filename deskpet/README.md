# DeskPet firmware

ESP32-S3 desk companion (ES3C28P board). Build with arduino-cli from this folder.

## Layout

```
deskpet/
├── deskpet.ino          Entry point (setup/loop). The folder and this file must share a name.
├── src/                 Firmware sources, grouped by layer. Quoted includes are root-relative,
│   │                    e.g. #include "src/core/audio/audio.h". arduino-cli compiles all of them.
│   ├── app/             Composition root: main loop, shared AppState, alarm and gesture model
│   │   ├── app.cpp
│   │   ├── state.h
│   │   ├── model.h
│   │   ├── settings_store.*  NVS persistence (debounced device settings, pet counter)
│   │   └── serial_console.*  Serial command parsing and status reports for the QA scripts
│   ├── core/            Hardware and platform services; no screens or pet logic
│   │   ├── audio/       audio.cpp, audio.h, ringtone_data.h (alarm ringtone PCM, generated)
│   │   ├── input/       touch_input.cpp, touch_input.h
│   │   ├── power/       battery.cpp, battery.h (battery voltage through the ADC)
│   │   ├── storage/     SD mounting, persistent boot record and file I/O diagnostics
│   │   └── system/      config.h, log.h, timekeeping.h
│   └── features/        User-facing features
│       ├── music/       SD library scanning, MP3/WAV decoding and playback controls
│       ├── pet/         Sprite pack decoder (pet_assets.*)
│       ├── setup/       Wi-Fi setup portal: SoftAP, network scan and web form (setup_portal.*)
│       ├── talk/        Talk mode: microphone in, higher-voice echo out (talk.*)
│       ├── ui/          Frame pipeline (ui.*), shared drawing helpers (ui_draw.*), fonts
│       │   │            (ui_assets.h, generated by tools/generate_ui_assets.py)
│       │   └── scenes/  One file per screen: pet, clock, weather, settings, music, setup
│       └── weather/     Weather fetch and parsing (weather.*)
├── partitions.csv       Partition table (PartitionScheme=custom reads it from the sketch root)
├── sketch.yaml          Board profile, core and library versions
├── arduino-cli.yaml     arduino-cli config (user dir = .arduino/)
├── assets/              Companion asset pack
│   ├── page-mascot/     Source sprite sheets and LICENSE
│   ├── pets.bin         Generated pack, flashed to the "assets" partition at 0x610000
│   ├── manifest.json    Generated summary of pets.bin
│   └── previews/        Preview images of the sprites
├── tools/               Host-side build, QA and serial probe scripts
├── qa/
│   ├── logs/            Captured serial and tool output (*.log)
│   ├── snapshots/       Framebuffer PNGs written by tools/verify_pet_assets.py
│   └── fixtures/        Saved device settings and alarm states
├── build/, out/         arduino-cli build path and output dir (generated)
└── .arduino/            arduino-cli user dir: installed libraries and cores
```

## Commands

Compile (run from this folder; use a different folder for `--build-path` and `--output-dir`):

```bash
arduino-cli compile --config-file arduino-cli.yaml --profile es3c28p --build-path build --output-dir out .
```

Regenerate assets:

```bash
python tools/generate_ui_assets.py
python tools/build_pet_assets.py
python tools/build_ringtone.py path/to/ringtone.mp3
```

Verify a connected board:

```bash
python tools/verify_pet_assets.py --port COM9
```

## Basic battery saving

- Music playback does not keep the backlight awake. After 60 seconds without
  interaction it dims to one quarter of the saved brightness (minimum PWM 3),
  while playback continues. A touch restores brightness. Alarm, setup and Settings
  retain their existing brightness behavior; this does not put the ESP32 to sleep.
- Setup Wi-Fi closes after 5 minutes without device or web activity. Opening the
  form, scanning, saving, and interacting with the form extend the timeout.
  A connected phone or abandoned browser tab alone does not keep it open.
  The device returns to the Pet page and reconnects to the saved network. Hold
  BOOT to open setup again. Without JavaScript, submit or reload within 5 minutes.
- After 1 second without interaction or serial traffic, the main loop waits up
  to 10 ms instead of 2 ms when idle. A queued touch wakes it immediately without
  consuming the sample. The touch sampler still runs every 10 ms. Music, Talk,
  alarms, held buttons/touches, reactions and pending display transfers retain
  the fast loop. Serial traffic restores the fast loop for uploads.

Host regression checks (run from the repository root; keep test executables outside it):

```bash
g++ -std=c++17 -Wall -Wextra -Werror -Ideskpet deskpet/tests/power_policy_test.cpp -o /tmp/deskpet-power-test
```

```bash
/tmp/deskpet-power-test
```

```bash
node deskpet/tests/setup_activity_test.cjs
```

These checks cover timing policy and browser activity signaling, not real current
consumption or physical touch/audio behavior. Before release, flash the board and
run `tools/perf_probe.py`, serial `selftest`, and `tools/verify_music.py`. Also check
music continues while the backlight dims, touching restores brightness, and setup
closes after inactivity but stays open while the form is being edited.

## SD card storage

DeskPet mounts the ES3C28P microSD socket automatically during boot using SDIO at
20 MHz. It tries 4-bit mode twice, then 1-bit mode once. A missing card or a mount
failure is logged and the app continues running. The firmware never formats a card.
Use a FAT-formatted card; the bundled ESP32 core does not enable exFAT support.

The card is mounted at `/sdcard`. DeskPet creates `/deskpet` on the card and writes
`/deskpet/boot.json` on each boot with the firmware version, reset reason, bus width
and card capacity. It reopens and compares the file before reporting the card as
writable. Existing settings remain in NVS; companions and ringtones remain in the
flash asset partition. Insert or remove the card while powered off; reboot after
changing cards. Runtime insertion and removal are not monitored.

The serial console at 115200 baud supports `sd-status` for the mount, capacity and
last error, and `sd-selftest` for a 128-byte write/read/compare/delete check using a
unique temporary file under `/deskpet`. The regular `status` response also includes
`sd_mounted` and `sd_writable`. The explicit self-test may pause the UI while waiting
for SD driver timeouts; the loop watchdog is suspended for this command and restored
when it returns.

Verify automatic mounting, real file I/O and mounting again after a reboot:

```bash
python tools/verify_sd_card.py --port COM9
```

## Music player

Copy MP3 or 16-bit PCM WAV files directly into `/music` on the card, or send them over
the USB cable with `tools/upload_music.py` (no card reader needed). Then open the Music
tab. The directory is created automatically. The player scans up to 64 files,
sorts them by name and shows three tracks per library page. Tap Library to choose a
track or rescan, and use Play/Pause, Previous, Next, Stop and the volume buttons.
Playback continues when changing pages; the next track starts automatically until
the end of the library. Booting never starts music automatically.

MP3 decoding uses ESP8266Audio 2.4.1, pinned in `sketch.yaml`. PCM WAV supports one
or two channels at 8–48 kHz. A worker reads and decodes files, converts them to mono
16 kHz and feeds a bounded audio queue; the existing speaker worker delivers that
queue to the codec. The progress bar represents file consumption, and elapsed time counts PCM
frames delivered to I2S. Unsupported characters in filenames display as `?` because
the display fonts contain ASCII only. File paths on the card remain unchanged.

Alarms stop music and take speaker priority. Talk mode is suspended while music is
loading, playing or paused. Stop releases the speaker for Talk again. The SD write
self-test is refused while a track is active. A corrupt or unsupported track shows
an error; it does not start an automatic loop of retries.

Serial commands: `music-status`, `music-list`, `music-scan`, `music-play <index>`
(zero-based), `music-pause`, `music-resume`, `music-stop`, `music-next`, `music-prev`.
Tabs run Pet, Clock, Weather, Music, Settings, so the Music page is `page 3` and
Settings is `page 4`.

Upload over USB serial (stop playback first; names must be plain ASCII). Each
file is read back and checked by CRC32 before it appears in the library:

```bash
python tools/upload_music.py --port COM9 "E:\Music\track.mp3"
```

The raw commands are `sd-put-begin <bytes> <name>`, `sd-put-data <base64>`,
`sd-put-end <crc32>` and `sd-put-abort`.

With two audible tracks of at least eight seconds on the card, verify playback,
pause/resume, navigation, saved settings and alarm priority:

```bash
python tools/verify_music.py --port COM9
```
